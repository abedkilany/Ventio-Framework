# G01 — Standard Printable Document Formats Acceptance

**Status:** Accepted  
**Capability:** G01 — Standard printable document formats  
**Accepted:** 2026-10-28  
**Platform target:** Flutter native client on Windows; PostgreSQL Host remains authoritative

## Delivered behavior

- Ordinary extension metadata now carries optional, bounded `printFormats`. Core accepts only scalar field blocks, Child Table blocks with declared scalar columns, and explicit page breaks. It rejects executable/unknown blocks, unknown source fields/columns, duplicate IDs, invalid label namespaces, and excessive counts. A print format has a stable English fallback, paper size, and orientation.
- Local drafts persist and reopen print formats in SQLite schema version 12. Export/import retains the format definitions and their English catalog labels. Studio lets an extension creator add an ordered field, child-table, or page-break block; table columns are selected from the declared Child DocType.
- The native print action is enabled only for a Host-accepted, non-pending, non-deleted record. It queries one exact record through the authenticated Host package client, requires the local package version and digest to match the approved package, and checks the returned revision and readable-field mask before rendering. It never prints a cached local snapshot.
- The fixed PDF renderer treats values as text, lays out scalar fields and bounded child rows, applies A4/Letter and orientation settings, and emits explicit page breaks. Windows Segoe UI is used with the installed Arial Unicode font as an optional Unicode fallback. Printing changes no record, numbering, lifecycle state, receipt, or queued command.

## Architecture and implementation

- [ADR-014 — Declarative Print Formats](ADR-014_DECLARATIVE_PRINT_FORMATS.md)
- Core contract: `packages/ventio_core/lib/src/print_format_metadata.dart`
- Package validation/round-trip: `packages/ventio_core/lib/src/extension_bundle.dart`
- SQLite store, ordinary Studio authoring, Host authorization, and PDF rendering are in `packages/ventio_native_client/lib/src/extension_store.dart`, `extension_studio_page.dart`, and `print_format_renderer.dart`.

The PDF output is generated by the trusted platform renderer from an approved data-only contract. Extensions provide no HTML, CSS, SQL, expression language, executable template, uploaded font, or renderer handler. No Host/Core inventory-specific code or PostgreSQL schema changes were needed for G01.
