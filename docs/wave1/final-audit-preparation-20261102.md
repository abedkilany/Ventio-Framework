## Security and defect disposition snapshot

- **Accepted security boundaries:** Stage 1 and 2 records cover scoped Host authorization, permission ceilings, forced PostgreSQL RLS/least privilege, Recovery Authority proof boundaries, redacted audit events, disable/revoke behavior and direct unauthorized/cross-scope rejection. Stage 6 process tests additionally verify protected diagnostic details are not returned through the public API.
- **No speculative recovery:** The office-machine `HOST_FIRST_ADMIN_RECOVERY_AUTHORITY_FAILED` remains unexplained. The supplied `pg_isready` authentication event is a readiness-check event and is not evidence of the bootstrap failure. Do not reset PostgreSQL, alter protected Recovery Authority state, weaken authentication or run an invented recovery procedure.
- **Potential release-blocking lifecycle risk:** Host installer/service lifecycle and installed recovery paths have not been demonstrated end to end in a clean elevated environment. This is an acceptance gap, not a newly proven runtime defect.
- **Installer evidence wording corrected:** The unified Inno package installs one shared Flutter application plus the Host payload; the app's first-run screen offers Host setup or Client connection. No installer type selector is present, and none is required by the implementation plan, which specifies the same Flutter application in either mode. The separate per-user Client package remains distinct. The former validate-unified-installer.ps1 SetupType parameter was label-only and has been removed; it never selected a mode in the installer. Neither its test label nor the separate Client package establishes that the unified artifact's installed lifecycle passed. That full lifecycle remains unverified.
- **Observed high-impact recovery defect; severity not formally classified:** Previous audit records identify `HOST_DATABASE_RECOVERY_ROLE_ROTATION_FAILED` from a partial installation as unresolved. The isolated `test-postgres-single-user-recovery.ps1` run now passes credential rotation, readiness/login and migration-ledger checks on a newly created disposable PostgreSQL cluster. It does not reproduce the historical failure against a copied database or explain the inaccessible office-machine report; the root cause remains unknown. Existing user data must not be used for that investigation.
- **Known diagnostic integration gap:** Operational event persistence and sanitized Diagnostics Center export are now demonstrated across independent Host process generations on an isolated local database. Persistence under the installed SCM service identity/reboot lifecycle and an actual failure through the installed pre-API setup UI are not demonstrated.
- **Commercial packaging status:** Both 2026-11-02 artifacts are Authenticode `NotSigned`; the Inno Setup compiler printed “Non-commercial use only,” and commercial toolchain-license status is unverified. No production/commercial-ready claim is supported.
- **Critical/high-severity review status:** The current evidence does not establish a fully closed security/release review for open setup, service, installer and recovery paths. No claim that the release has zero critical/high defects is made. Stage 9 must perform and record the final source/security review after those lifecycle tests are available.
- **Development workstation state:** Read-only checks found `VentioHost` and `VentioPostgres` registered as `Automatic` but `Stopped`; `127.0.0.1:8080/healthz` refused at the recorded check. The current process token is not elevated. A read-only SCM query confirms that VentioHost declares VentioPostgres as a dependency; both services are stopped, and VentioHost reports Win32 exit 1068. No attempt was made to start, stop or reconfigure either service. Hyper-V services are running and the account is in Hyper-V Administrators. A no-disk capability probe confirmed VM registration/removal access and was removed immediately; Get-VM now lists no registered VM. The checked Hyper-V directory contains only the Ventio Ubuntu CI VHDX, not a Windows guest. No Windows Sandbox executable or Windows installation image was found in the checked standard locations. The current `flutter devices` listing contains Windows, Chrome and Edge only; no Android device is attached. This does not explain the Ventio service state or contradict separate owner screenshots from another Windows 11 computer.

The official [Windows 11 Enterprise Evaluation](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise) flow requires registration and Microsoft-account sign-in; the general [Windows 11 ISO page](https://www.microsoft.com/en-us/software-download/windows11) describes a multi-edition image unlocked by a product key. No evaluation account or Windows VM product key was supplied for use, and no personal account was used. No large OS image was downloaded. The clean elevated Windows installer/service gates therefore remain blocked; this does not authorize or require changes to the existing Ventio services or product data.
